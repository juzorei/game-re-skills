# Scope and acceptable use

These skills teach an agent the reverse-engineering workflow behind game modding: finding data in memory, describing it in a way that survives updates, and reading it from your own tools.

## In scope

- Single-player and offline games.
- Modding, trainers for your own single-player use, accessibility tools, overlays and data exports.
- Interoperability and research on software you own a copy of.
- Private servers and test environments you run yourself.
- Learning how engines, compilers and memory layouts work.

## Out of scope

- Bypassing, disabling or hiding from anti-cheat (EAC, BattlEye, Vanguard, VAC and similar), including kernel drivers and detection evasion.
- Cheating in online multiplayer or gaining an advantage over other players.
- Cracking DRM or license checks, or redistributing game files.

When a request falls outside this scope, the agent should say so plainly and offer the in-scope part if one exists (for example, studying the same engine in an offline build).

## Your responsibility

Game terms of service vary. Reading another process's memory can break them even in single-player titles with online components. Check the rules for the game you're working on.
